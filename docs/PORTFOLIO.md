# 플랜두씨 다이어리 · 포트폴리오 소개

## 한 줄 소개

예상 시간과 실제 실행의 차이를 원본 기록으로 확인하고, 회고를 다음 계획으로 연결하는 개인 생산성 웹 애플리케이션.

## 프로젝트 소개

플랜두씨 다이어리는 계획을 세우고, 실행을 기록하고, 결과를 돌아보는 Plan–Do–See 흐름을
구현한 웹 애플리케이션입니다. 계획한 시간과 실제 집중 시간을 별도로 보존하며, 회고 화면에서
일곱 개 지표와 각 숫자의 근거 기록을 함께 확인할 수 있습니다. 회고에서 정한 개선점은 다음
계획에 그대로 이어져 기록과 다음 행동이 연결됩니다.

React·TypeScript 프런트엔드와 Flask·PostgreSQL 백엔드로 구성했고, Docker 이미지 하나를
Render에 배포했습니다. 공개형으로 시작한 T06 다이어리를 T07에서 개인 계정 기반으로
확장하면서, 기존 자료 이관과 서버의 소유권 검증, 비밀번호 저장, 세션 만료·폐기까지
구현했습니다. 기능의 정상 동작뿐 아니라 다른 사용자의 자료 접근, 중복 요청, 만료되거나
재사용된 인증값이 거절되는 동작도 자동 검사와 요청·응답 증거로 남겼습니다.

## 주요 구현

- **집계와 근거의 일치:** 같은 조회 결과에서 집계값과 원본 기록 ID를 함께 계산합니다.
  예상값을 실행값으로 덮어쓰지 않으며, UTC 저장과 서울 날짜 판정을 구분합니다.
- **즉시 폐기할 수 있는 인증:** Access JWT를 DB 세션에 연결해 로그아웃 이후의 요청을
  거절합니다. 비밀번호 변경 시 기존 모든 세션을 폐기하고 현재 기기에 새 세션을 발급합니다.
- **Refresh 회전과 재사용 탐지:** 사용한 Refresh는 새 값으로 교체하고, 이미 교체된
  토큰이 다시 요청되면 같은 세션 계열을 폐기합니다. DB에는 원문 대신 해시를 보관합니다.
- **계정별 데이터 격리:** 서버가 확인한 사용자 ID로 목록·단건·집계·내보내기의 범위를
  제한합니다. 두 계정 사이의 읽기·수정·삭제 요청을 양방향으로 검사합니다.
- **중복 요청과 데이터 이관:** 완료 처리에 멱등 키와 DB 제약을 적용합니다. 기존 데이터는
  백업 후 소유권을 부여하고, 미소유 자료가 없는지 확인한 뒤 필수 제약을 적용했습니다.

## 검증 근거와 진행 상태

2026-09-11 실제 5일 관찰 증거를 포함한 로컬 검사 결과는 백엔드 319개 통과·3개 건너뜀,
프런트엔드 76개 통과이며 프로덕션 빌드도 통과했습니다. PostgreSQL 전용 검사 3개는
2026-09-05 별도 Neon 테스트 브랜치에서 확인했습니다. 2026-09-07~11 관찰에서 하루 계획
대비 실제 비율은 규칙 변경 전 0.63배, 변경 후 0.40배, 전체 0.56배였습니다. 이 짧은
자기 관찰만으로 일반적인 생산성 향상 효과를 주장하지 않습니다.

운영 Render 인스턴스에서 선택한 Argon2id 설정의 비밀번호 검증 시간은 p50 108ms,
p95 197ms였습니다. 이는 비밀번호 검증 연산의 측정값이며 로그인 API 전체 응답 시간이
아닙니다. 별도 `/settings` 페이지는 자동 검사와 데스크톱·모바일, 라이트·다크 화면 검수를
마쳤습니다.

이메일 소유 확인과 비밀번호 재설정은 구현하지 않았습니다. Refresh 회전 응답을 잃은 뒤
이전 토큰을 재시도하면 재로그인이 필요할 수 있으며, 이런 한계도 인증 설명서에 기록했습니다.

## 포트폴리오에 사용할 화면과 캡션

| 화면 | 캡션 |
| --- | --- |
| [로그인](screenshots/login-hero.png) | 개인 기록에 접근하기 전 세션을 확인하는 로그인 화면 |
| [회원가입](screenshots/signup-hero.png) | 비밀번호 조건·강도·일치를 안내하고 서버에서 정책을 재검증하는 가입 화면 |
| [계획](screenshots/plan-light.png) | 예상을 기준선으로 고정하고 실제를 겹쳐, 계획끼리 비교할 수 있는 막대 |
| [실행 기록](screenshots/do-light.png) | 예상 시간을 보존하며 실제 시간과 막힌 이유를 별도 기록 |
| [회고](screenshots/see-light.png) | 일곱 개 집계 지표에서 숫자의 근거가 되는 원본 기록까지 확인 |
| [설정](screenshots/settings-light.png) | 프로필·내보내기·보안을 세 구획으로 나누고, 되돌릴 수 없는 계정 삭제만 따로 표시 |

위 이미지는 저장소의 기존 합성 데이터 화면입니다. 로그인·가입 화면을 먼저 배치하고,
Do·See 화면으로 핵심 사용 흐름을 설명할 수 있습니다. 설정 화면은 합성 계정으로 촬영했으며
실제 개인 기록은 촬영하지 않았습니다. 표의 링크는 라이트 화면이고, 모든 화면에 같은
이름에 `-dark`를 붙인 다크 화면이 함께 있습니다. `/app` 화면 넉 장은
`tools/seed_screenshot_fixture.py`가 심은 같은 합성 자료 한 벌에서 나왔습니다.
