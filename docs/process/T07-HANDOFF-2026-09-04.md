## 4. 배포 순서 — 그날 그대로 따라갈 것

`deploy/start.sh`가 `flask db upgrade`를 **BOOT_TASK보다 먼저** 돌린다. 그래서 claim과
NOT NULL은 **같은 배포에 실을 수 없다.** 마이그레이션이 스스로 거부하고 배포를 세운다.

| | 하는 일 | 확인 |
| --- | --- | --- |
| 배포 A | 저장소 연결을 T07로 전환. `BOOT_TASK=claim_t06_data`, `BOOT_TASK_ARGS=--apply` | 로그에 `NULL=0` |
| — | `BOOT_TASK=none`으로 되돌리고 push | |
| 배포 B | `d5a3e91c7f20`까지 올라간다 (NOT NULL 포함) | `/api/live` 200 |
| 그다음 | 관찰 계획을 만들고 그 ID를 `OBSERVATION_PLAN_ID`에 넣는다 | 그 계획의 기록 날짜 0개 |

### Render 환경변수

`render.yaml`에 다 적혀 있다. **대시보드에서 값을 넣어야 하는 것**:

| 키 | 값 |
| --- | --- |
| `DATABASE_URL` | T06 Neon 그대로 |
| `CLAIM_EMAIL` · `CLAIM_PASSWORD` | 이관받을 계정. **명령줄 인자로 주지 말 것** |
| `OBSERVATION_PLAN_ID` | 관찰 계획을 만든 뒤에 |

`JWT_SECRET`과 `IP_HASH_SECRET`은 `generateValue: true`라 Render가 만든다. **둘은 서로
달라야 한다** — 서명 키를 돌린다고 로그인 제한 창까지 초기화되면 안 된다.

claim 대상 ID는 이미 실물 DB로 검증했다: 계획 7개 전부 분류, 삭제될 4개는 살아 있는 할 일
0개, 제외할 할 일 2개는 둘 다 이미 soft-delete 상태.

## 5. 다음 작업 — 16번 유휴·절대 만료

**로직은 이미 있다.** `app/services/sessions.py`가 `last_used_at + idle_ttl()`을 회전과
가드 양쪽에서 본다. 절대 만료는 `test_c111_absolute_expiry_survives_rotation`이 이미
잡고 있다. 없는 것은 매트릭스가 약속한 `test_c111_idle_expiry` 하나다 — 48시간 쓰지 않은
세션이 회전에서 401을 받고, 그 401이 「모르는 토큰」과 구별되지 않는지.

그다음이 17번(비밀번호 변경 + 전 세션 폐기)이다. `test_c114_password_change_revokes_all_sessions`
는 이미 있으니, 필요한 것은 엔드포인트와 폐기·경합 처리다.

### 15번은 끝났다 (`app/services/throttle.py`)

```
창       15분
임계     같은 (email, ip_hash) 실패 5회  또는  같은 ip_hash 실패 20회
잠금     60초 → 배증 → 최대 15분. 계정 조회·Argon2보다 먼저 계산한다
해제     로그인 성공 시 그 (email, ip_hash)의 failure 행만 삭제
```

알아 둘 것 넷:

- `blocked`는 세지 않는다. 세면 공격자가 요청만 계속 보내 피해자를 15분 붙들 수 있다.
- 없는 계정·파싱 실패한 본문도 센다. 안 세면 「안 잠긴다 = 없는 계정」이 된다.
- 성공은 그 쌍만 푼다. IP 전역 카운트는 남긴다 — 자기 계정 하나로 전역 제한을 지울 수 없게.
- **`MAX_LOCK`이 `WINDOW`와 같다.** 60→120→240→480초를 다 견디면 처음 실패들이 창 밖으로
  나가므로, 상한은 산수로만 도달한다. 그래서 사다리는 `_lock_for`를 직접 검사한다.

검사는 `backend/tests/acceptance/test_t07_login_throttle.py` 14개. **`test_c` 접두사를 쓰지
않았다** — 고정 기준에 없는 검사이고, 매트릭스 가드가 그 접두사를 예약해 두었다.

## 6. 최근에 알아낸 것 (다시 부딪히지 않게)

- **`refresh_is_live`가 재사용 탐지를 가로막는다.** 순차 재생은 사전 검사에서 401로 끝나
  회전 코드까지 못 간다. 그래서 진입점이 둘이다 — `spent_by_rotation`(사전 검사)과 회전의
  `reused` 플래그(동시 충돌). 비슷한 검사를 추가할 때 **사전 검사가 삼키지 않는지** 보라.
- **동시 refresh 두 건은 계열을 끊는다.** 진 쪽이 `rotated`를 보고, 그건 재생과 구별되지
  않는다. 유예 창은 도둑에게도 유예를 준다. 프런트가 직렬화하는 이유가 이것이고, 알고
  남긴 대가다(설계 11절).
- **`secure_cookies()`는 `TESTING`에서만 꺼진다.** 예전엔 `REQUIRE_POSTGRES` 기준이었는데,
  브라우저는 `Secure` 없는 `__Host-` 쿠키를 스킴과 무관하게 거부한다. 개발 브라우저의
  로그인이 조용히 아무것도 저장하지 않고 있었다.
- **내보내기 계약 가드가 새 표를 막는다.** 표를 추가하면 `contracts/pds-schema-v2.json`에
  분류(내보냄/보류)하기 전까지 `test_card5_export.py`가 실패한다. 의도된 것이다.
- **매트릭스 가드**: `test_c…`로 시작하는 테스트 이름은 `docs/T07-ACCEPTANCE-MATRIX.md`에
  적힌 것이어야 한다. 기준에 없는 검사는 `test_c` 접두사를 쓰지 않는다.
- **PostgreSQL cascade 검사 2건은 스킵 중.** `TEST_DATABASE_URL`을 주면 돈다. 18번 할 때
  반드시 한 번 돌려 볼 것.
- 마이그레이션 head는 `d5a3e91c7f20`.
