## 1. 무엇으로 붙이는가 ★ — **미결**

> 이 절은 **아직 결정되지 않았다.** 아래 표는 초안일 뿐이고, 판단 재료는
> `docs/T07-AUTH-OPTIONS.md`에 따로 정리했다. 그 문서가 요구하는 **측정 두 개**(해싱
> 비용·세션 조회 비용)를 하기 전까지 여기 적힌 조합은 확정이 아니다.
> 아래 2~10절은 「서버 저장 세션」을 전제로 쓰여 있으므로, 층 ②를 바꾸면 3·4절도 바뀐다.

### 초안으로 놓은 것

| 층 | 고른 것 | 이유(한 줄) |
| --- | --- | --- |
| 비밀번호 보관 | **argon2-cffi** (Argon2id) | 소금값·매개변수를 해시 문자열 안에 스스로 담아, 내가 손댈 여지를 남기지 않는다 |
| 사람을 기억하는 법 | **직접 구현한 서버 저장 세션** (불투명 난수 + DB 테이블) | 로그아웃이 서버에서 진짜로 끊겨야 하는데(C114), 그걸 증명하려면 서버에 끊을 대상이 있어야 한다 |
| 세션 운반 | **HttpOnly·Secure·SameSite 쿠키** | 값이 주소창에 실리지 않아야 한다(C112) |

즉 답은 **"라이브러리 하나(argon2-cffi) + 직접 구현(세션)"** 이고, 설명서 ①에는 이 두
가지를 갈라서 적는다. C107은 *비밀번호를 다루는 부분*만 라이브러리를 요구하므로 이
조합이 기준을 벗어나지 않는다.

### 검토했지만 고르지 않은 것 (C93)

- **인증 서비스(Auth0·Supabase Auth·Clerk)** — 비밀번호 해시가 남의 서버에 남아서,
  "내 데이터베이스에 저장된 비밀번호 값"(C103)과 "같은 비밀번호로 만든 두 계정의 저장된
  값이 다름"(C104)을 **제출문에 보일 방법이 없다**. 이 과제에서는 고를 수 없는 선택지다.
- **Flask-Login 기본 세션(서명 쿠키)** — 로그아웃이 브라우저 쿠키를 지울 뿐이라, 그
  쿠키를 그대로 다시 보내면 서버가 여전히 받아 준다. C109·C114가 요구하는 "로그아웃 뒤
  같은 값 → 거절" 장면이 나오지 않는다.
- **JWT(무상태 토큰)** — 로그아웃을 만들려면 결국 서버에 폐기 목록을 둬야 하는데, 그러면
  무상태라는 장점이 사라지고 세션 테이블보다 부품만 늘어난다.

설명서 ②에는 위 세 줄을 그대로 옮긴다.

## 2. 데이터 구조

### 새 표 두 개

```
users
  id                uuid pk
  email             citext unique not null      -- 소문자로 정규화해 저장
  password_hash     text not null               -- argon2id 인코딩 문자열
  password_changed_at  timestamptz not null
  created_at / updated_at
  (비밀번호 원문·힌트·질문 없음)

sessions
  id            uuid pk
  user_id       uuid fk -> users.id on delete cascade
  token_sha256  char(64) unique not null   -- 원본 토큰은 저장하지 않는다
  issued_at     timestamptz not null
  expires_at    timestamptz not null
  revoked_at    timestamptz null
  last_seen_at  timestamptz not null
```

**세션 토큰을 그대로 저장하지 않는 이유**: 데이터베이스가 새면 그 값으로 곧장 로그인이
된다. 비밀번호와 같은 이유로 해시만 둔다. 다만 토큰은 128비트 난수라 사전 공격 대상이
아니므로 argon2가 아니라 SHA-256으로 충분하다 — 이 판단도 설명서에 적는다.

### 기존 표에 붙는 것

`plans.user_id`(FK, NOT NULL)를 **소유권의 유일한 뿌리**로 둔다. tasks·executions·
reflections·plan_revisions는 `user_id`를 따로 갖지 않고 **plans를 거쳐 주인을 판정**한다.

> 비정규화(각 표에 user_id 복사)를 하지 않는 이유: 두 곳에 적힌 주인이 어긋나는 순간
> 어느 쪽이 참인지 코드가 답할 수 없다. 조인 한 번이 그 위험보다 싸다.

### T06 자료를 내 계정으로 옮기기 (C100)

세 단계 이관으로, 중간에 주인 없는 행이 생기지 않게 한다.

1. `user_id`를 **nullable로 추가**
2. `backend/scripts/claim_t06_data.py` — 환경변수로 받은 이메일·비밀번호로 계정을
   만들고, `UPDATE plans SET user_id = :id WHERE user_id IS NULL` 실행
   (비밀번호는 인자로 받고 **로그에 남기지 않는다**)
3. 다음 마이그레이션에서 **NOT NULL로 조인다**

옮기지 않을 것: T06 공개 앱에 남은 `프로젝트 테스트` 계획과 `<script>` 문자열이 든
삭제 완료 상태의 할 일은 이관 대상에서 뺀다. 이관 스크립트가 무엇을 옮기고 무엇을
버렸는지 건수로 출력하고, 그 출력을 증거로 남긴다.

## 3. 요청이 지나는 길 (설명서 ③의 뼈대 · C128)

```
요청
 └ app/auth/guards.py : @login_required
      쿠키에서 토큰 → SHA-256 → sessions 조회
      없음 / revoked_at 있음 / expires_at 지남  → 401
      통과하면 g.current_user 를 채운다
 └ app/services/ownership.py : owned_plan(id) / owned_task(id) / owned_reflection(id)
      select(...).join(Plan).where(Plan.user_id == g.current_user.id)
      한 건이라도 못 찾으면 → 404 (있는데 남의 것 / 아예 없음을 구별해 주지 않는다)
 └ 기존 서비스 계층 (T06 그대로)
```

거절을 만드는 자리는 **이 두 파일뿐**이다. C126에서 "거절을 만들어 내는 소스 위치"로
가리킬 곳이 한 군데로 모이도록 일부러 이렇게 나눈다. API 함수 안에서 각자 주인을
확인하게 두면, 나중에 한 곳을 빠뜨렸을 때 그것을 찾을 방법이 없다.

### 새 엔드포인트

| 메서드·주소 | 하는 일 | 관련 기준 |
| --- | --- | --- |
| `POST /api/auth/signup` | 계정 생성 | C94 · C98 |
| `POST /api/auth/login` | 세션 발급, 쿠키 심기 | C95 · C99 |
| `POST /api/auth/logout` | `sessions.revoked_at` 기록, 쿠키 삭제 | C96 · C109 |
| `GET  /api/auth/me` | 현재 사용자 | 프런트 게이트 |
| `POST /api/auth/password` | 비밀번호 변경 + **전 세션 폐기** | C114 |
| `DELETE /api/account` | 계정과 자료 함께 삭제 | C134 |
| `GET  /api/export` | **내 자료만** 파일 하나로 | C133 · C125 |

기존 T06 엔드포인트 22개는 주소를 바꾸지 않는다. `@login_required` + `owned_*` 두 줄만
앞에 붙는다. 주소가 그대로여야 "T06에서는 열리던 것이 T07에서는 401"이라는 장면이
같은 주소로 찍힌다.

### 거절 규격 (C121)

| 상황 | 응답 |
| --- | --- |
| 로그인 안 함 | `401` `{"error":{"message":"로그인이 필요합니다."}}` |
| 남의 자료 | `404` — **403이 아니다** |
| 아이디 없음 / 비밀번호 틀림 | `401` `{"error":{"message":"이메일 또는 비밀번호가 올바르지 않습니다."}}` — **두 경우 완전히 같은 문자열·같은 코드** (C99) |

404를 고르는 이유: 403은 "그 ID는 있다"를 알려 준다. 남의 계획 ID를 훑어 존재 여부만
모으는 일을 막으려면 없는 것과 구별되지 않아야 한다. C121이 명시적으로 허용한다.

**아이디 없음일 때도 argon2 검증을 한 번 헛돌린다.** 안 그러면 응답 시간이 달라
아이디 존재 여부가 새어 나가, 문구를 같게 맞춘 뜻이 없어진다.

## 4. 세션 규칙

- **만료**: 발급 후 **14일 절대 만료**. 슬라이딩 연장 없음 — 연장이 있으면 "얼마 뒤
  끊기는지"(C111)를 한 문장으로 못 적는다.
- **쿠키**: `HttpOnly; Secure; SameSite=Lax; Path=/`. 도메인 지정 없음.
- **주소창 금지**(C112): 토큰은 쿠키로만 오간다. 쿼리스트링·경로에 절대 넣지 않는다.
- **비밀키 없음**(C113): 토큰은 `secrets.token_urlsafe(32)` 난수이고 **서명하지 않는다**.
  서명 비밀키가 아예 존재하지 않으므로 브라우저 코드·배포 파일·Git에 샐 값이 없다.
  `backend/scripts/audit_secrets.py`에 세션 쿠키 이름·토큰 모양 패턴을 추가해 계속 확인한다.
- **폐기 경로**: 로그아웃 → 그 세션 하나. 비밀번호 변경 → 그 사용자의 모든 세션.
  계정 삭제 → cascade.

### CSRF

쿠키 인증이라 교차 사이트 요청이 붙을 수 있다. 두 겹으로 막는다.

1. `SameSite=Lax` — 남의 사이트의 폼 POST가 쿠키를 달고 가지 못한다.
2. 상태를 바꾸는 요청은 `Content-Type: application/json`을 요구한다. 브라우저가 교차
   출처로 이 헤더를 붙이려면 프리플라이트를 거쳐야 하고, CORS를 열지 않았으므로 막힌다.

토큰 방식 CSRF 방어는 넣지 않는다. **이 판단은 설명서 ⑥에 그대로 적는다** — 위 두
겹이 뚫리는 조합(구형 브라우저 등)이 남아 있기 때문이다.

## 5. 화면

지금 앱은 라우터가 없는 한 화면짜리다. C03·C97을 보이려면 **주소가 갈려야 한다**.

- `react-router-dom` 도입 ★
- `/login`, `/signup` — 로그인하지 않아도 열린다 (C03: 심사자가 계정 없이 여기까지는 봄)
- `/app` — 자료 화면. 로그인 안 했으면 **`/login`으로 보낸다** (C97)
- Flask에 SPA 폴백 라우트 추가: `/login`·`/signup`·`/app` 직접 접근 시 `index.html`
- `/` 는 `/login`으로 (로그인 상태면 `/app`)

T06 첫 화면의 **"지금은 로그인이 없어 링크를 아는 사람은 누구나 볼 수 있습니다" 문구를
지운다.** 더는 사실이 아니고, 남겨 두면 그 자체로 감점 사유다.

계정 화면(`/app` 안): 비밀번호 변경 · 내보내기 · **계정 삭제**(지워진다는 안내 문구 포함, C134).

## 6. 5일 실사용과 규칙 변경 (카드 5)

이건 코드보다 **기록 구조**의 문제다. C09~C15는 "규칙 변경 기록이 2일차 뒤·3일차 앞에
놓이고, 1일차와 2일차 기록을 정확히 가리킬 것"을 요구한다. 문서로만 적으면 순서를
증명할 수 없으므로 표를 하나 더 둔다.

```
plan_rule_changes
  id, plan_id, changed_at (timestamptz),
  reason (text),
  rule_before (text), rule_after (text),
  cited_execution_ids (json)   -- 1일차·2일차 기록의 ID를 정확히 가리킨다 (C12)
```

`docs/T07-STUDY-PROTOCOL.md`에 1일차에 **한 번만** 고정할 것들을 적는다 —
질문 한 문장(C04) · 지표 하나(C05) · 단위(C06) · 계산 규칙(C08) · 결측(C23) ·
중복(C24) · 이상값(C25) · 반올림(C26) · 주 시작 요일(C27).

**지표 확정(2026-09-03)**: **하루 계획 대비 실제 비율** — 단위 `배`, 계산 `실제분 ÷ 예상분`,
소수 둘째 자리 반올림. T06에서 이미 게이지로 쓰던 축이라 5일 비교가 자연스럽다.
1일차에 한 번 고정하고 5일 내내 바꾸지 않는다(C05·C06·C08·C13~C15).

5일은 실제로 매일 채워야 하므로 **오늘(2026-09-03)부터 시작해도 5일차는 2026-09-07**이다.
구현을 그 전에 끝내야 한다는 뜻 — 일정상 이게 가장 빡빡한 제약이다.

## 7. 증거 수집 구조 (④ · C129)

"막았습니다"가 아니라 장면이 필요하므로, 증거를 **손으로 캡처하지 않고 스크립트로
찍는다**. 손으로 모으면 비밀값을 가리는 것을 잊는다.

```
backend/scripts/collect_auth_evidence.py
  → 계정 두 개 생성 → 자료 넣기 → 양방향 읽기·수정·삭제 시도
  → 로그아웃 후 같은 쿠키 재사용 → 미로그인 직접 호출
  → 거절 전후 건수 비교
  → docs/T07-EVIDENCE/*.md 로 출력, 토큰·비밀번호는 출력 단계에서 마스킹
```

마스킹은 **출력 함수 한 곳**에서 한다(`redact()`). 마스킹을 호출부마다 하면 언젠가
한 곳을 빠뜨리고, 그게 곧 C131 위반이다.

증거 파일 목록:

| 파일 | 담는 것 | 기준 |
| --- | --- | --- |
| `01-signup-login-logout.md` | 가입·로그인·로그아웃, 중복 가입 거절, 같은 문구 두 경우 | C94~C99 |
| `02-password-storage.md` | 저장된 해시 한 개, 같은 비밀번호 두 계정의 서로 다른 해시 | C101~C107 |
| `03-session.md` | 같은 주소·같은 방식 성공/거절 쌍, 만료, 비밀번호 변경 후 폐기 | C108~C115 |
| `04-cross-account.md` | 양방향 읽기·수정·삭제, 헤더·본문 위조, 미로그인, 목록, 건수 대조 | C116~C126 |
| `05-totals.md` | 화면 합계·평균과 손으로 더한 값 | C132 |

## 8. ⑥ 아직 못 막은 것 — 지금 시점의 후보 (C130)

비워 두면 안 되는 항목이라 미리 정직하게 적어 둔다. 구현하면서 지우거나 늘린다.

- **무차별 대입** — 계정당 시도 제한을 넣더라도 IP를 바꿔 가며 여러 계정을 훑는 공격은
  못 막는다. 흔한 비밀번호를 쓴 계정이 열린다.
- **비밀번호 재설정 없음** — 잊으면 복구 수단이 없다. 편의 문제이자, 급하게 붙이면
  거기가 가장 약한 고리가 되는 자리다.
- **두 번째 인증 수단 없음** — 비밀번호 하나가 새면 그걸로 끝이다.
- **이메일 소유 확인 없음** — 남의 이메일로 가입할 수 있다.
- **감사 로그 없음** — 누가 언제 들어왔는지 남지 않아, 털린 뒤에 알아낼 방법이 없다.
- **CSRF 토큰 없음** — 4절에서 적은 두 겹에 기대고 있다.
